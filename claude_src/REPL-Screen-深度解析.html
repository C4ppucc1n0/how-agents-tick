一句话结论：原文说，src/screens/REPL.tsx 是 Claude Code 的交互中枢。它是一个 5061 行的 React 组件，用 Ink 渲染终端界面。用户和 Claude 之间的全部交互都经过它。

  • 组件树：最外层是错误边界 ReplRuntimeBoundary。FullscreenLayout 把界面分成可滚动的内容区和固定的底部栏。

概述

原文“概述”

REPL.tsx 承载用户和 Claude 之间的全部交互。从输入提交、消息渲染、流式输出、工具调用可视化，到权限对话框、会话恢复、快捷键处理，都在这里。

REPL 的名字来自 Read-Eval-Print Loop。原文说，它在 Claude Code 里不再是简单的“输入、求值、输出”循环，而是一套完整的 TUI 框架。原文列出它包含五部分，下表把它们对应到本页各节（本页归纳）：

消息的 Deferred 渲染

为了在流式输出时保持输入响应，REPL 用 React 18 的 useDeferredValue 得到一份低优先级的 deferredMessages。流式输出时，每个 content delta 都会更新 messages。

下表据原文的代码和说明整理，usesSyncMessages 等于“显示流式文本，或不在加载中”：

情形 usesSyncMessages 渲染方式
正在加载，不显示流式文本 ✗假 deferredMessages 以较低优先级渲染
显示流式文本 ✓真 切换为同步模式
查询已完成 ✓真 切换为同步模式

deferredBehind 是 messages 比 deferredMessages 多出的条数。它大于 0 时写调试日志，便于性能分析。

原文 7

onSubmit：输入提交枢纽

原文说 onSubmit 是 REPL 里最复杂的回调之一，职责如下：

职责 做法
滚动 调用 repinScroll()，视图滚到底部
立即命令 检测 / 前缀，判断是否为 immediate 类型，直接执行 local-jsx 命令
空闲回归检测 检查 tengu_willow_mode 和空闲时间，决定是否弹出 IdleReturnDialog
历史记录 调用 addToHistory()
Stash 管理 保存和恢复 stashedPrompt
推测接受 接受 Prompt Suggestion 的“猜测模式”
远程模式 处于 remote、direct-connect 或 SSH 模式时，用 activeRemote.sendMessage() 发送
本地查询 调用 handlePromptSubmit()，走完整的本地查询流程

handlePromptSubmit：核心处理

handlePromptSubmit 来自 src/utils/handlePromptSubmit.js。它解析输入（slash 命令、bash 命令、普通文本），展开 skill 引用，构建 UserMessage，再调用 onQuery 或执行命令逻辑。E 节的流程图画出了这一段。

输入模式

inputMode 的类型是 PromptInputMode，取值 prompt 或 bash，默认 prompt。

  • prompt 模式：普通对话，输入直接作为用户消息发给 Claude。
  • bash 模式：输入以 ! 开头，Shell 命令直接执行，输出注入对话上下文。

Typeahead 与命令补全

PromptInput 用 commands 列表和输入历史做自动补全。useMergedCommands 分两步合并三类命令源：本地命令先和插件命令合并，结果再和 MCP 命令合并，得到 mergedCommands。

队列处理器

查询执行期间提交的新输入，会排进命令队列（useCommandQueue）。查询完成后，useQueueProcessor 自动按顺序处理队列里的命令。

错误状态与恢复

原文 9

ReplRuntimeBoundary

REPL 外面包着一个 React 错误边界 ReplRuntimeBoundary。下图据原文的类代码绘制：

原文说，有了这个错误边界，REPL 树里部分组件崩溃时，终端会话不会整个崩溃，而是进入“降级回退模式”。

错误恢复机制

  • onInit() 错误处理：初始化出错时，用 addNotification 显示“startup degraded”通知，不终止会话。
  • 状态恢复：resume() 回调从磁盘恢复会话时，重建完整状态。
  • 紧凑化恢复：消息紧凑化后，runPostCompactCleanup() 执行清理，让内存状态和磁盘状态一致。
