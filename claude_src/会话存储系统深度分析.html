会话存在哪、怎么用

官方文档说，会话是一段保存下来的对话，和项目目录绑定。Claude Code 边用边把它存在本地，所以你能接着上次聊，也能分出一个分支试别的做法。

你怎么做 效果（官方文档） 原文对应的部分
正常对话 会话存成 ~/.claude/projects/<project>/<session-id>.jsonl。<project> 是工作目录路径，非字母数字的字符换成 -；超过 200 个字符就截断，再加上完整路径的哈希 C、D、E 节
运行 claude --continue 重新打开当前目录最近的会话 G 节
运行 claude --resume，或在会话里输入 /resume 打开会话列表，选一个恢复；--resume <名字> 直接恢复那个会话 G 节
输入 /branch，或在 --continue、--resume 后加 --fork-session 复制当前对话，切到副本里接着聊，原会话不变 H 节
输入 /compact [指令]；上下文快满时自动压缩 用摘要替换历史。恢复压缩过的会话时，对话从 Conversation compacted 这一行开始 F 节
输入 /rewind，选一条消息，再选 Summarize from here 或 Summarize up to here 只压缩一部分对话 F 节（部分压缩）
运行 claude -p 时加 --no-session-persistence 这次运行不写会话文件 L 节（延迟物化）

两点补充（官方文档）：

  • 子 Agent 的对话另存在 ~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl。主对话压缩时，这些文件不受影响。
  • 会话文件里每行的格式是 Claude Code 内部的，版本之间会变。写脚本读会话数据，官方建议用 /export 或 claude -p --output-format json，不要直接解析这些文件。
原文和官方文档的说法不同
  • 分叉的参数：原文概述写 --fork，6.1 节和生命周期图写 --fork-session。官方文档用 --fork-session，会话里用 /branch。
  • 回退的按键：原文 5.5 节说回退是 Ctrl-Z。官方文档里，回退（rewind）是 /rewind，或在输入框为空时连按两次 Esc；Ctrl+Z 是把 Claude Code 挂起到 shell，只在 Unix 上有。
  • 子 Agent 文件名：原文 6.1 节的表写 subagents/<agentId>.jsonl，6.3 节写 subagents/agent-<agentId>.jsonl。官方文档和 6.3 节一样。

C

文件格式规范

原文 一、1.1–1.3

白话：会话文件一行一条记录。有的行是对话消息，有的行是元数据，例如标题。对话消息之间靠 parentUuid 串起来。

JSONL 格式

会话文件用 JSONL 格式：每一行是一个独立的 JSON 对象，用换行符 \n 分隔。文件存在 ~/.claude/projects/<sanitized-cwd>/<sessionId>.jsonl。

  • <sanitized-cwd>：当前工作目录清理后的安全路径名。非字母数字的字符换成 -；路径太长就截断，再加哈希后缀。
  • <sessionId>：一个 UUID v4。

原文给了四行示例。下表按示例整理：

行 type 关键字段 说明
1 user parentUuid 为 null，uuid 为 a1b2… 第一条用户消息
2 assistant parentUuid 为 a1b2…，uuid 为 c3d4… 回复第 1 行
3 summary leafUuid 为 c3d4…，summary 为摘要文字 压缩摘要，指向第 2 行
4 custom-title customTitle 为“修复登录bug” 用户自定义标题

Project 类：核心管理器

原文 二、2.1–2.4

白话：Project 是负责写会话文件的对象，整个程序只有一个（单例）。写文件不是来一条写一条，而是先排进队列，每隔 100ms 一次写一批。“尾部窗口”指文件最后 64KB。恢复时的会话列表只读这一段来取标题等信息（原文 5.3 节），所以元数据要留在这一段里。

类职责

会话文件生命周期管理 创建、写入、清空会话文件

元数据缓存 缓存会话标题、标签、Agent 名称和颜色等
远程持久化 通过 CCR v2 内部事件或 Session Ingress API 写到远程

压缩机制

原文 四、4.1–4.5

白话：

  • 压缩边界：压缩时写进文件的一条标记消息。它的 parentUuid 是 null，所以从后往前串对话时，到这里就停。边界之前的旧消息还在文件里，但恢复时用不到。
  • PTL：Prompt Too Long，请求内容超过模型能接受的长度。
  • Hook：用户配置的、在某个时刻自动运行的命令，例如压缩之前（PreCompact）。

触发条件

压缩分两种：

  • 自动压缩：src/services/compact/autoCompact.ts 里的 autoCompactIfNeeded()，在每轮对话后检查令牌数是否超过阈值。
  • 手动压缩：用户运行 /compact。

会话恢复（Resume）流程

原文 五、5.1–5.7

白话：恢复分两步。先快速列出所有会话给你挑，只看文件名、修改时间和每个文件头尾各 64KB。你挑中一个，再完整读这个文件，把对话串起来。读之前先剔除“死分支”：回退或分叉以后，旧的对话路线还留在文件里，但已经不属于当前对话。

只追加（Append-Only）

原文说，所有写入都是在文件尾部追加，从不修改已写入的行。所以写入很快（均摊 O(1)），但也会积累死数据。压缩机制和 walkChainBeforeParse() 在读取侧解决这个问题。

延迟物化（Lazy Materialization）

会话文件在第一条 user 或 assistant 消息到达时才创建（见 E 节）。原文列的好处：

  • 空会话不产生文件。
  • 只含元数据的简短操作不创建文件。
  • 支持用 --no-session-persistence 完全关掉。
