一句话结论：原文认为，Print/Output 系统是一条多层、高度优化的输出管道。

  • 给人看：交互模式下，用 Ink 在终端里画出完整界面，Markdown、代码高亮、表格都转成终端能显示的格式。
  • 给程序读：非交互模式（--print）下，把结果写成纯文本、JSON 或逐行的 JSON（NDJSON），供管道和 SDK 使用。

先认识几个词

下面这些词全篇反复出现，先用白话说清。其他名词见文末“附录：名词表（白话）”。

词 白话
终端、TUI 终端是输入命令、显示文字的窗口。TUI 是在终端里用文字画出的界面，有边框、颜色和滚动区域。平时运行 claude 看到的就是 TUI
stdout、stderr 程序往外写文字的两条通道。stdout 写正常结果，stderr 写错误和提示。两条都显示在屏幕上，但可以分开接到不同地方
管道（|） 把前一个程序的 stdout 接到后一个程序的输入。原文的例子 claude -p '...' | head -1，就是把 Claude 的输出交给 head，只留第一行
ANSI 转义序列 夹在文字里的控制码，终端不把它显示出来，而是照着做，例如“下面的字变红”“加粗”“移动光标”
Markdown 用符号标格式的纯文本写法，例如 **粗体**、# 标题。Claude 的回复就是 Markdown
解析、Token 解析是把一段文字拆开，认出每部分是什么。拆出来的每一块叫 Token，例如一个标题、一段代码
JSON、NDJSON JSON 是程序之间常用的文本数据格式。NDJSON 是每行一条 JSON，读的一方按行读，每行就是一条完整的消息
渲染 把数据变成屏幕上看得见的样子。本文里指把回复画成终端里的文字和颜色

Markdown 终端渲染

原文「Markdown 终端渲染」

白话：终端不认识 **、# 这些 Markdown 符号。这一节讲怎样把它们变成终端里的粗体和颜色。做法是先用 marked 库把文本解析成 Token，再把每个 Token 换成带 ANSI 控制码的文字。

marked.js 集成

Claude Code 用 marked 库做 Markdown 的词法分析。src/utils/markdown.ts 里的 configureMarked() 只配置一次，改掉 marked 的删除线规则，让 ~ 不再被解析成删除线。

原文给的理由：AI 模型常用 ~ 表示“近似”（如 ~100），很少真要删除线。关掉删除线解析，可以避免大量误解析。

双路径渲染

src/components/Markdown.tsx 按文本里有没有 Markdown 语法，走两条路径。下图按原文的图重画：

原文列的三项优化：

优化 做什么 原文给的数值
快速语法检测 hasMarkdownSyntax() 用一次正则检查开头的字符。完全没有 Markdown 语法，就跳过 marked.lexer 的完整 GFM 解析，直接构造一个单段落 Token 检查前 500 个字符；完整解析约 3ms
MRU Token 缓存 一个 LRU 缓存，按内容哈希查找。滚动查看历史消息时，解析过的 Token 直接从缓存取，不再重复解析 最多 500 条
流式 Markdown 渲染 StreamingMarkdown 组件在最后一个稳定块的边界切开，只重新解析后面不稳定的部分 —

白话：流式输出时，回复是一点点到的。“稳定块”是已经完整、不会再变的部分；最后那段还在增长，是“不稳定的后缀”。

formatToken 函数

formatToken() 是 Markdown 渲染的核心。它把 marked 产生的 Token 树递归地转成带 ANSI 转义序列的字符串。原文列的 Token 类型：

Token 类型 是什么 在终端里怎样显示
blockquote 引用 暗色竖线前缀（chalk.dim），文字用斜体（chalk.italic）
code 代码块 交给 cli-highlight 做语法高亮（见 E 节）
codespan 行内代码 用主题色 permission 着色
em、strong 斜体、粗体 分别用 chalk.italic 和 chalk.bold
heading 标题 h1 用粗体、斜体加下划线；h2 及更低级的标题只加粗
link 链接 用 OSC 8 超链接转义序列；邮箱链接按纯文本处理
list 列表 支持嵌套：第 1 层用数字，第 2 层用字母，第 3 层用罗马数字
table 表格 自动算列宽，处理对齐，按 ANSI 样式换行

原文两处讲到表格：上面的图里，Markdown 组件把表格 Token 交给 MarkdownTable 组件（见 K 节）；这张表里 formatToken 也处理 table。原文没有说两者怎样分工。

formatToken 还会把 GitHub Issue 引用转成超链接：文字里出现 owner/repo#NNN 格式，就用 OSC 8 链接到 https://github.com/owner/repo/issues/NNN。识别靠一条正则 ISSUE_REF_PATTERN。

结构化输出模式

原文「结构化输出模式」；并入原文「输出缓冲与流式控制」

白话：这一节讲非交互模式下，输出怎样交给程序。

  • stream-json：Claude Code 和调用它的程序（原文叫 SDK 宿主，例子是 VS Code 和 CCR）通过 stdin、stdout 一行一行地传 JSON 消息。stdin 是程序读入文字的通道。

主循环每收到一条消息，就决定马上写出去，还是先存起来。

NDJSON 行协议

SDK 模式用 NDJSON（Newline-Delimited JSON，每行一条 JSON）通信，StructuredIO 类管理整个协议。据原文 J 节的矩阵，StructuredIO.read() 按行读取并解析 stdin 上的消息，StructuredIO.write() 把 NDJSON 写到 stdout。

ndjsonSafeStringify() 保证 JSON 字符串里不含 JavaScript 的两个行终结符：U+2028（LINE SEPARATOR）和 U+2029（PARAGRAPH SEPARATOR）。它把这两个字符分别转义成 \u2028 和 \u2029。原文给的理由：有的接收端会把它们错认成行分隔符。

--output-format=json 在会话结束时，把消息序列化成 JSON 写到 stdout：

原文说这是一项内存优化：只有 json 加 verbose 时，才在内存里累积完整的消息数组；默认只保留 lastMessage。
