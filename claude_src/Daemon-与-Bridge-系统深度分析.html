原文：Daemon 与 Bridge 系统深度分析

一句话结论：原文认为，Bridge 和 Daemon 一起组成分层的远程控制与进程管理架构。

  • Bridge：让用户在 claude.ai 网页或手机上操控本地会话。它正在从“经 Environments API 轮询领工作”演进到“直接连会话入口”。
  • Daemon：长期运行的后台监督进程，负责生成和回收 worker。所有会话都在 ~/.claude/sessions/ 下登记 PID 文件。原文说它的监督逻辑还在按 feature flag 逐步交付。

白话地说（本页归纳）：Bridge 让你人不在电脑前，也能用手机指挥电脑上的 Claude；Daemon 让你关掉终端以后，Claude 还能在电脑上接着干。

A

先看懂：两个功能在用户眼里是什么

本页补充：前半据官方文档；全局结构为本页归纳，据原文第 3、4 节

这篇文章讲的是源码。读源码之前，先看这两个功能用起来是什么样子。

Bridge：在手机上指挥电脑上的 Claude

官方文档把这个功能叫“远程控制”（Remote Control）。

  • 你先在自己的电脑上开着 Claude Code，再用手机上的 Claude App 或任意浏览器（claude.ai/code）打开同一个会话。
  • 你在手机上打字、批准操作；Claude 在电脑上读写文件、运行命令。
  • 手机只是一个窗口，活都在电脑上干。所以电脑要开着，claude 进程也不能关。
  • 手机和电脑不直接连接，两边都连到 claude.ai 的服务器，由服务器转发。电脑只向外发请求，不开放任何端口，所以不用设置路由器。

容易混的一点（官方文档）：claude.ai/code 上还有一种“云端会话”。它在 Anthropic 的机器上运行，用不到你的电脑。远程控制在你自己的电脑上运行，所以能用本地的文件、工具和 MCP 配置。

Daemon：让 Claude 在后台接着干

官方文档里，对应的功能叫“后台会话”。

  • 运行 claude --bg "任务描述"，会话直接转到后台运行。关掉终端，它也不停。
  • 运行 claude agents，打开一个列表，看所有后台会话在干什么、哪个在等你回复。
  • 运行 claude attach <id> 回到某个会话，claude logs <id> 看它最近的输出，claude stop <id> 停掉它。

这些后台会话由一个“监督进程”（supervisor）运行，官方文档也叫它后台服务。第一次把会话放到后台时，它自动启动，不用你管。

  • 每个后台会话是监督进程下面一个单独的 Claude Code 进程。
  • 会话的进程意外退出，监督进程就重新启动它。
  • 会话闲着约一小时，监督进程就停掉它的进程，省资源。对话存在磁盘上，你下次回来时接着聊。
  • claude daemon status 显示监督进程的状态。

词 白话

子进程 一个进程启动的另一个进程。Bridge 收到任务后新开的 Claude Code，就是 Bridge 的子进程
服务器、请求 服务器是网上一台一直开着、等别人来连的计算机。你的电脑向它发“请求”，它回“响应”。本文的服务器是 claude.ai 的

B

两条实现路径

原文 1、1.1

白话：手机上发来的任务先到 claude.ai 服务器，电脑上的 Bridge 再把它取回来执行。原文说取任务有两种做法。

  • 老做法（路径一）：电脑先在服务器上登记一个“环境”，意思是“这台机器可以接活”。然后不停地问服务器有没有给它的活；有，就在本地新开一个 Claude Code 进程去干。
  • 新做法（路径二）：不登记环境，也不问活。电脑直接和某个会话建立连接，收发消息。

图里的 POST /v1/environments 这类写法，是向服务器的某个地址发请求：POST 一般用来提交数据，GET 一般用来取数据。

Bridge 让用户在 claude.ai 网页或移动应用上，远程操控本地运行的 Claude Code 会话。原文说它的代码在 src/bridge/ 下，约 30 个 TypeScript 文件，超过 1 万行。

Bridge 有两条实现路径。

路径一：基于环境的传统路径

这条路径由 bridgeMain.ts 和 replBridge.ts 实现，通过 Environments API 调度工作。本地先注册一个“环境”，再不停向服务器要工作。服务器给了会话工作，本地就起一个子 Claude Code 进程去跑。

C

工作轮询引擎

原文 1.2

白话：这一节讲路径一里“不停地问服务器有没有活”的那个循环。

  • 没活，就接着问；有活，就开一个 Claude Code 进程去干。
  • 出错了，就等一会儿再问。每多失败一次，等的时间就更长，直到上限，这叫“指数退避”。
  • 同时干活的数量到了上限，电脑就改发“心跳”：定期发一个小请求，告诉服务器“我还在”。原文说心跳用来延长“租约”，也就是在一段时间内占用某项资源的权利，要定期续，过期就失效。

路径一的核心是 runBridgeLoop 里的主循环：中止信号没触发，就一直向服务器要工作。

要点 做什么 原文给的参数

D

传输层：WebSocket 与 SSE

原文 1.3

白话：电脑和服务器之间要一直收发消息，这一节讲用什么连接来收发。

  • WebSocket：一条连上就不断开的双向连接，两边随时都能发消息；v1 用它收消息。
  • SSE：服务器单向往电脑推消息的连接，v2 用它收消息。电脑要发消息时，另外发普通的 HTTP POST 请求。
  • 断线以后：要能自动重新连上，还不能把收过的消息再收一遍。v2 的做法是给每条消息编号（序列号），重连时告诉服务器“我已经收到第几号了”，服务器只发后面的。

表里的“批量”指先攒几条消息，再一次发出去；“串行”指同一时刻只发一个请求，上一个完成了才发下一个。

Bridge 支持两种传输协议。原文的对比表如下：

特性 v1（HybridTransport） v2（SSETransport + CCRClient）
读取 WebSocket SSE（Server-Sent Events）
写入 HTTP POST（批量） HTTP POST 到 CCR /worker/*
SDK URL ws(s)://.../session_ingress/ws/{id} https://.../v1/code/sessions/{id}
注册 POST /v1/environments POST /v1/code/sessions/{id}/bridge
重连 WS 自动重连（10 分钟预算） SSE 自动重连 + 401 恢复
序列号 0（无 SSE seq-num） SSE sequence-number 高水位
去重 服务端消息游标 from_sequence_num / Last-Event-ID

SSE 是服务器单向推送事件的 HTTP 长连接。

E

消息中继与去重

原文 1.4

白话：中继就是转发：电脑上 Claude 输出什么，就转给手机；手机上输入什么，就转给电脑上的 Claude。

  • 去重：网络重连、会话重启时，同一条消息可能被发两遍，或者自己发出去的又被自己收回来。所以每条消息带一个唯一编号（UUID），记下见过的编号，再见到就丢掉。
  • 控制请求：这类消息不是聊天内容，而是指令，例如“允许这次工具调用”“中断”“换模型”。
  • 图里的“NDJSON stdout”：子进程把每条消息写成一行 JSON 文本，写到标准输出，Bridge 一行一行地读。标准输出（stdout）是程序默认往外写文字的通道。

Bridge 的核心功能，是在本地 REPL 和远程 claude.ai 之间中继消息。

三层去重

机制 防止什么 怎么做
BoundedUUIDSet 自己发出的消息被回声注入；服务端重播入站消息 用 2000 项的环形缓冲区记住出站消息的 UUID，入站消息也按 UUID 去重

控制请求

bridgeMessaging.ts 的 handleServerControlRequest 处理服务器发来的控制请求，例如权限提示、中断、切换模型和切换权限模式。sessionRunner.ts 的 PermissionRequest 类型，对应 subtype 为 can_use_tool 的 control_request。它用来逐次检查每个工具调用的权限。

F

安全模型

原文 1.5

白话：远程控制要保证两件事：发指令的人确实是你，接指令的电脑确实是你那台；主要靠“令牌”。

  • OAuth 令牌：你登录 claude.ai 时拿到的令牌，Bridge 用它代表你向服务器发请求。
  • JWT：另一种令牌，里面直接写着身份、权限和过期时间，这里发给单个会话用。
  • 401：服务器的回复代码，表示身份验证没通过，例如令牌过期。这时先换新令牌，再重发原来的请求。
  • 组织策略：公司或团队管理员给成员设的规则，例如是否允许远程控制。

原文把 Bridge 的安全措施分成几层：

措施 保护什么 怎么做

Worker 通信协议

原文 2.5

白话：几个进程之间要互相传话，原文总结里列了三种渠道。

  • UDS（Unix 域套接字）：同一台电脑上两个进程直接传数据的通道，不经过网络。
  • 环境变量：启动 worker 时一次性把配置交给它。
  • PID 文件：让别的进程找到 worker。

这一节最后讲怎样停掉一个进程，用到两种“信号”：SIGTERM 请进程自己收尾后退出；SIGKILL 由系统直接结束进程，进程来不及收尾。

worker 进程通过几种渠道通信。

UDS 收件箱

UDS 是同一台机器上进程间通信用的本地 socket。功能 UDS_INBOX 打开时，每个 worker 把自己的 socket 路径（messagingSocketPath）写进 PID 文件。这样能给某个 worker 单独发消息，不用靠轮询共享文件。原文还说，sessionIngressAuth.ts 的 updateSessionIngressAuthToken “暗示”有一套入站认证 token 的更新机制，用来验证 UDS 消息。

在用户这一侧（官方文档）：这种收件箱对应“跨会话消息”功能，一个会话可以给本机另一个会话发消息。socket 的路径就放在环境变量 CLAUDE_CODE_MESSAGING_SOCKET 里；在 macOS 和 Linux 上是 Unix 域套接字，在 Windows 上是命名管道（named pipe）。

环境变量

worker 通过环境变量接收配置和认证信息。原文的表如下：

环境变量 用途 设置者
CLAUDE_CODE_SESSION_KIND 会话类型 生成进程
CLAUDE_CODE_SESSION_ACCESS_TOKEN Session Ingress JWT bridge
CLAUDE_CODE_SESSION_NAME 可读的会话名称 生成进程
CLAUDE_CODE_SESSION_LOG 日志文件路径 生成进程
CLAUDE_CODE_AGENT Agent 标识 生成进程
CLAUDE_CODE_USE_CCR_V2 启用 v2 传输 bridge
CLAUDE_CODE_WORKER_EPOCH CCR v2 的 worker epoch bridge

原文说，Daemon 监督进程（daemon/main.ts）管理整棵进程树：生成 worker；用 CLAUDE_CODE_SESSION_KIND=daemon-worker 标记 worker；用 PID 文件追踪 worker 生命周期；worker 死掉时重新生成或通知用户。

  • Agent SDK：原文说 Agent SDK 是 Daemon 的主要使用方之一（SDK 模式下的 --assistant 标志）。Daemon 代 SDK 管理 worker 生命周期，Bridge 负责和 claude.ai 通信。claude_code_assistant 这种 worker 类型，让 claude.ai 的会话选择器能按来源过滤：assistant 标签页只显示 assistant worker。
